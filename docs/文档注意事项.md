# DLZ-DB 8.0 文档维护注意事项

本页记录文档与 8.0 源码对齐时最容易写错的约定。以当前源码公开签名和模块配置为准，不从历史文档反推 API。

## 入口与分层

- 稳定业务入口：`DB.pojo`、`DB.table`、`DB.jdbc`、`DB.sql`、`DB.batch`、`DB.ds`、`DB.tx`、`DB.config`。
- 业务代码优先使用 `com.dlz.db`、`com.dlz.db.wrapper`、`com.dlz.db.model`、`com.dlz.db.option` 和 `com.dlz.db.core.anno` 中的公共类。
- `com.dlz.db.internal.*` 是实现包，不应出现在新的业务示例中。当前 `Condition` 仍位于 internal，因此文档不再推荐用户显式声明或复用 `Condition`，直接在 Wrapper 上构造条件。

## 常用 API 命名

- 创建 Wrapper：`selectWrapper`、`insertWrapper`、`updateWrapper`、`deleteWrapper`。
- 选择查询列：`.select(...)`，不是 `.columns(...)`。
- 复合条件：`.ands(...)` 表示括号内 AND，`.ors(...)` 表示括号内 OR。
- 分页：Wrapper 使用 `.page(1, 20).queryBeanPage()` 或 `.queryPage()`；直接 JDBC API 使用 `DB.jdbc.page(sql, PageRequest.of(1, 20), ...)`。
- 查询数量：`.count()` 返回 `long`。
- 写 Wrapper 通常以 `.execute()` 结束；`DB.pojo.insert(entity)`、`updateById`、`deleteById` 等直接方法已立即执行。

## 返回值

- `queryOne/queryFirst/queryList/queryPage` 返回 `ResultMap` 系列。
- `queryBean/queryFirstBean/queryBeanList/queryBeanPage` 返回 Pojo 系列。
- `queryOne(Class)`、`queryList(Class)`、`queryPage(Class)` 映射为指定类型。
- `Page` 位于 `com.dlz.db.model.Page`，记录集通过 `getRecords()` 或 `records()` 取得。
- 批量方法返回 `BatchResult`，用 `isSuccess()`、`status()`、`failedPositions()` 和 `cause()` 检查结果。

## Spring Boot 与 Solon

- Spring Boot Starter 会自动装配 `SpringDlzDbAutoConfiguration`；应用无需继承配置类，也不存在 `SpringDlzDbConfig`/`SpringDlzDbProperties` 这组当前 API。
- Spring Boot 2 通过 `spring.factories` 加载，Spring Boot 3 通过 `AutoConfiguration.imports` 加载。
- Solon 插件入口是 `DlzDbSolonPlugin`，并在容器中获得 `DataSource` Bean 后初始化。只有 YAML 连接信息但没有可用的 `DataSource` Bean 不足以完成初始化。

## JDK 与验证

- `dlz-db-core`、Spring Boot 2 示例和 Solon 示例的编译目标是 Java 8。
- Spring Boot 3 示例需要 JDK 17。因此聚合构建所有 demo 时应使用 JDK 17。
- 默认构建跳过 JaCoCo 和 SpotBugs；不要在文档中把 `mvn ... jacoco:report` 写成当前一定可用的根项目命令。

## 文档审查清单

1. 代码片段至少兼容 Java 8；不在通用文档中使用文本块、`Map.of` 等高版本语法。
2. 将文档中的类名、包名和方法名与 `src/main/java` 再比对。
3. 历史迁移记录必须明确标注版本，不把 6.x/7.x 的类名当成 8.0 用法。
4. 测试数、覆盖率和性能数字必须标注生成日期与对应版本，不作为当前发行结论。
