# 4.4 FAQ

## Q: 如何处理复杂的 JOIN 查询？

使用原生 SQL 或预设 SQL：

```java
String sql = "SELECT u.*, d.name AS dept_name "
    + "FROM user u "
    + "LEFT JOIN department d ON u.dept_id = d.id "
    + "WHERE u.status = ?";
List<ResultMap> list = DB.jdbc.selectWrapper(sql, 1).queryList();
```

## Q: 如何实现乐观锁？

```java
int updated = DB.pojo.updateWrapper(User.class)
    .set(User::getName, newName)
    .set(User::getVersion, user.getVersion() + 1)
    .eq(User::getId, user.getId())
    .eq(User::getVersion, user.getVersion())
    .execute();

if (updated == 0) {
    throw new OptimisticLockException("数据已被修改");
}
```

## Q: 如何调试 SQL？

开启 `dlz.db.log.show-run-sql` 后，日志会显示展开参数的 SQL 和执行耗时。开启 `show-caller` 会向 MDC 注入调用方信息，是否显示取决于日志 pattern。展开 SQL 用于排查，复制到数据库工具前仍应检查敏感值、方言和转义结果。

## Q: 性能和 MyBatis 比怎么样？

DLZ-DB 底层基于 JDBC，但端到端性能还取决于 SQL、结果映射、日志、连接池和数据库。没有统一的性能结论；请在实际数据集上用相同 SQL 做 benchmark。

## Q: 能和 MyBatis 共存吗？

依赖层面可以同时引入，DLZ-DB 不依赖 MyBatis 体系。如果两者需要共享数据源或 Spring 事务，应针对实际数据源、事务管理器和连接获取路径做集成测试，不应仅根据“能启动”就推断事务语义一致。
