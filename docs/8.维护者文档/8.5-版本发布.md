# 8.5 版本发布

DLZ-DB 通过 Maven Central Publisher Portal 发布。发布配置位于根 POM 的
`central-publish` Profile；凭证和签名私钥只保存在发布者本机或 CI Secret 中，不能提交到仓库。

## 1. 发布产物

一次正式发布包含以下坐标：

- `top.dlzio:dlz-db`：聚合 POM。
- `top.dlzio:dlz-db-core`：框架无关核心包。
- `top.dlzio:dlz-db-spring-boot-starter`：Spring Boot 集成包。
- `top.dlzio:dlz-db-solon-plugin`：Solon 集成包。

`dlz-db-web-demos` 及其子模块仅参与构建验证，已配置跳过 `install` 和 `deploy`，不属于发行物。
三个 JAR 模块发布时必须同时生成主 JAR、sources JAR 和 javadoc JAR，并对 POM 与所有附件执行 GPG 签名。

## 2. 本机前置条件

1. 使用 JDK 17 或更高版本执行完整 reactor 构建；主库产物仍以 Java 8 为目标。
2. Maven Central Portal 中已验证 `top.dlzio` namespace。
3. `~/.m2/settings.xml` 中存在 ID 为 `central` 的 server，用户名和密码使用 Portal 生成的 User Token。
4. GPG 中存在可用私钥，公钥已发布到可访问的公钥服务器。

`settings.xml` 只保留在本机或 CI 环境，结构如下：

```xml
<server>
    <id>central</id>
    <username>Portal Token 用户名</username>
    <password>Portal Token 密码</password>
</server>
```

完整要求以 [Central Publisher Portal 的 Maven 文档](https://central.sonatype.org/publish/publish-portal-maven/)
和 [Central 发布要求](https://central.sonatype.org/publish/requirements/) 为准。

## 3. 发布前检查

发布前确认：

- Git 工作区干净，待发布提交已推送并通过全部 CI。
- 根 POM、模块 POM、README、快速开始和 CHANGELOG 中的版本一致。
- 当前版本从未发布到 Maven Central；Central 上的已发布版本不可覆盖或删除。
- API/SPI 兼容性和 internal 泄漏检查已经完成。

在仓库根目录执行 CI 等价验证：

```bash
mvn -B clean verify --file pom.xml "-Djacoco.skip=false"
```

再验证发布附件生成，但不执行远程发布：

```bash
mvn -B -Pcentral-publish "-Dgpg.skip=true" package
```

检查三个发行模块的 `target/`，应同时存在主 JAR、`-sources.jar` 和 `-javadoc.jar`。

## 4. 正式发布

```bash
mvn -B -Pcentral-publish clean deploy
```

`central-publish` 会生成 sources/javadoc、执行 GPG 签名、上传 Central Portal，并在校验成功后自动发布，
等待状态变为 `published` 后才结束。该操作不可撤销，执行前必须再次确认版本号和 Git 提交。

不要使用裸 `mvn deploy`：默认构建没有远程仓库配置，因而会报告缺少
`distributionManagement` 或 `altDeploymentRepository`。这是有意的保护，避免普通构建误发布。
如果只是让其他本地项目引用当前代码，应执行 `mvn install`，而不是 `mvn deploy`。

## 5. 发布后检查

1. 在 Central Portal 确认部署状态为 `PUBLISHED`。
2. 等待 Maven Central 索引同步后，核对四个发行坐标及 POM、sources、javadoc、签名附件。
3. 从一个不依赖本仓库 reactor 的空白项目解析三个 JAR 坐标。
4. 将 CHANGELOG 中的版本从“待发布”改为正式发布日期，并创建对应 Git tag 和 GitHub Release。
