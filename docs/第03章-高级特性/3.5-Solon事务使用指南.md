# 3.5 Solon 事务使用指南

Solon 环境支持两种事务方式：Solon `@Tran` 声明式事务，以及框架无关的 `DB.tx.run(...)` 编程式事务。

## 前提

- `dlz-db-solon-plugin` 已通过 SPI 加载。
- Solon 容器中已经有 `DataSource` Bean。
- 如果使用 `@Tran`，项目需按 Solon 要求引入并启用对应事务能力。

## 编程式事务

```java
DB.tx.run(() -> {
    DB.pojo.insert(order);
    DB.pojo.insert(orderItem);
});

Long id = DB.tx.run(() -> {
    DB.pojo.insert(order);
    return order.getId();
});
```

指定数据源：

```java
DB.tx.run("slave", () -> {
    DB.pojo.insert(user);
});
```

`DB.tx.run(name, ...)` 等价于在该数据源上切换并建立本地事务。它不是跨数据源分布式事务。

## 嵌套语义

```java
DB.tx.run(() -> {
    DB.pojo.insert(order);
    DB.tx.run(() -> DB.pojo.insert(orderItem));
});
```

对同一 `DataSource`，内层 `DB.tx.run` 检测到已有绑定连接后会加入外层事务，不独立提交或回滚。任务抛异常时由最外层新建事务回滚。

如果内层切换到另一数据源，它会使用另一条连接和独立本地事务；两个数据源之间没有原子提交协调。

## 声明式事务

```java
@Component
public class OrderService {
    @Tran
    public void createOrder(Order order, List<OrderItem> items) {
        DB.pojo.insert(order);
        for (OrderItem item : items) {
            item.setOrderId(order.getId());
            DB.pojo.insert(item);
        }
    }
}
```

`SolonTxExecutorAdapter` 会通过 `TranUtilsBridge` 检测 Solon 原生事务上下文；在已有 `@Tran` 事务时，`DB.tx.run` 不再开新的同数据源事务。

## 异常与限制

- 新建的 `DB.tx` 事务在回调正常返回时提交，抛出异常时回滚并转为 `DbException`。
- 当前 `ITxExecutor` 只承诺 REQUIRED 式的加入语义，不提供 `REQUIRES_NEW` 或 `NESTED`。
- 不要在事务回调内启动新线程并期望事务上下文自动传播；连接绑定是线程本地的。
- 批量操作不天然等于全有或全无；需要整体回滚时将它放入 `DB.tx.run(...)`。

简要用法也可参考 [3.4 事务管理 - Solon](./3.4-事务管理-Solon.md)。
